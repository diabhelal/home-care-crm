## 1. בעיה ומטרה
כשסוג ביקור אינו זמין זמנית (למשל בדיקות דם) אין דרך לסגור אותו בלי שינוי הגדרות ופריסה. המנהל צריך להשהות שירות, לכתוב הודעה למטופל ולחדש אותו, מתוך הממשק.

## 2. היקף
**בהיקף:** השהיה לטווח תאריכים או עד לחידוש; הודעה למטופל (עד 200 תווים); חידוש; אכיפה בטופס, ב-backend וב-DB; שורות לא נמחקות.
**מחוץ להיקף:** הוספת סוג שירות חדש או הסרה קבועה (נשלט ב-`OFFERED_PURPOSES` ו-`SERVICE_CONFIG`); ביטול אוטומטי של הזמנות קיימות; השהיה לפי איש צוות; התראה למטופלים שכבר הזמינו.

## 4. דרישות חדשות או שונות
אין דרישה חדשה: FR-BK-18 מכסה את הפיצ'ר. סטטוס "ממומשת/נבדקה" יעודכן רק אחרי מיזוג PR #35, וה-SQL (הצעה `021`) יישאר "מתוכננת" עד החלה על המסד החי באישור נפרד.

## 5. השפעה
**הרשאות:** כתיבה למנהל בלבד (RLS); קריאה ציבורית רק דרך פונקציה שמחזירה שירות, תאריכים והודעה. **מסד נתונים:** טבלה חדשה, פונקציות וטריגרים, כהצעה בלבד. **תיעוד רפואי:** אין. **אופליין:** הבקשה דורשת חיבור כמו כל הזמנה. **שפות:** מחרוזות חדשות בעברית, אנגלית וערבית.
